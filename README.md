## 🎯 О проекте

Проект реализует полный пайплайн **обнаружения мошеннических транзакций** с банковскими картами с использованием unsupervised-методов машинного обучения.

**Ключевые особенности:**
- Задача относится к классу сильно несбалансированных (`contamination ≈ 0.17%`, соотношение классов ~1:578)
- Признаки V1–V28 получены методом **PCA** и анонимизированы
- Применяются 4 алгоритма обнаружения аномалий с последующим сравнением
- Визуализация структуры данных через **t-SNE** и **UMAP**

## 🔬 Методология

### 1. Разведочный анализ данных (EDA)

- Проверка пропусков и типов данных
- Анализ дисбаланса классов (лог-шкала)
- Гистограммы всех 30 признаков
- Описательные статистики ключевых признаков

### 2. Предобработка данных

```python
# Масштабирование всех признаков
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)
```

- Применяется `StandardScaler` для всех признаков
- Параметр `contamination` вычисляется из реальной доли аномалий

### 3. Модели обнаружения аномалий

| # | Модель | Принцип | Особенности реализации |
|---|--------|---------|----------------------|
| 1 | **EllipticEnvelope** | Робастная ковариационная матрица | Предполагает гауссово распределение |
| 2 | **Isolation Forest** | Случайные изолирующие разбиения | `n_jobs=-1`, полный датасет |
| 3 | **One-Class SVM** | Гиперплоскость в RBF-пространстве | Обучение на 20% данных (ускорение), предсказание на всех |
| 4 | **Local Outlier Factor** | Оценка локальной плотности | `n_jobs=-1`, режим `fit_predict` |

Все модели используют единый `contamination_value`, равный реальной доле фрода.

### 4. Визуализация структуры данных

Для наглядного анализа расположения аномалий применяются методы снижения размерности на 10% подвыборке данных:

- **t-SNE** — `perplexity=30`, `n_iter=1000`
- **UMAP** — `n_components=2`

### 5. Оценка качества

Из-за сильного дисбаланса классов **Accuracy не используется** как основная метрика.

Ключевые метрики для класса 1 (мошенничество):

| Метрика | Назначение |
|---------|-----------|
| **Precision (1)** | Доля верно найденных фродов среди всех предсказанных |
| **Recall (1)** | Доля найденных фродов среди всех реальных |
| **F1-score (1)** | Гармоническое среднее Precision и Recall — **главная метрика** |
| Predicted Anomaly Fraction | Соответствие предсказанной доли аномалий реальной |

## 📈 Результаты

### Сравнение моделей

| Модель | Precision (1) | Recall (1) | **F1 (1)** | Predicted Anomaly Fraction |
|--------|:---:|:---:|:---:|:---:|
| EllipticEnvelope | 0.018 | 0.018 | 0.018 | 0.0017 |
| **🏆 Isolation Forest** | **0.256** | **0.256** | **0.256** | **0.0017** |
| OneClassSVM | 0.061 | 0.644 | 0.112 | 0.0181 |
| LocalOutlierFactor | 0.000 | 0.000 | 0.000 | 0.0017 |

### 🏆 Лучшая модель — Isolation Forest

**Обоснование:**

1. **Максимальный F1 (0.256)** — в 2.3× лучше OneClassSVM и на порядки лучше остальных
2. **Точная оценка загрязнения** — предсказанная доля (0.17%) = реальная → нет ложного «шума» алертов
3. **Соответствие природе данных** — PCA-признаки с тяжёлыми хвостами хорошо разделяются случайными разбиениями; аномалии лежат в разреженных зонах (подтверждено UMAP)
4. **Масштабируемость** — линейная сложность, `n_jobs=-1`, работает на 285k записей
5. **Гибкость порога** — anomaly score позволяет настраивать порог под бизнес-задачу

### Выводы по остальным моделям

- **EllipticEnvelope** — не применима: признаки имеют негауссовское распределение с тяжёлыми хвостами
- **OneClassSVM** — высокий Recall (64%), но Precision всего 6%; доля предсказанных аномалий в 10× завышена (1.8% vs 0.17%)
- **LocalOutlierFactor** — F1 = 0 при текущих гиперпараметрах; требует тщательной настройки `n_neighbors` и `contamination`

### Визуализация

На проекциях t-SNE и UMAP видно, что:
- Часть мошеннических транзакций образует **изолированные кластеры** — их легко выделить методами изоляции
- Часть аномалий **«маскируется»** внутри нормальных кластеров — это фундаментальная сложность задачи

## 🔮 Направления для улучшения

- [ ] **Тюнинг Isolation Forest**: перебор `contamination`, `n_estimators`, `max_samples` по PR-AUC
- [ ] **Supervised-модели**: XGBoost / LightGBM с `scale_pos_weight` или SMOTE (ожидаемый F1 = 0.7–0.85)
- [ ] **Ансамблирование**: anomaly scores IF и OCSVM как признаки для supervised-модели
- [ ] **Autoencoder**: ошибка реконструкции как признак аномальности
- [ ] **Инжиниринг признаков**: `hour = (Time // 3600) % 24`, log-трансформация `Amount`
- [ ] **Оптимизация порога**: настройка под бизнес-метрику (стоимость FN vs FP)
